## Binding Product network contract, distinct from existing V1

1. Owner alone creates/edits a Product's identity, network Inbound→explicit Host selections and positive multiplier. The **Product editor exposes Inbound and Host, not an independent Node chooser, quota/days/devices/base-rate or fixed-price editor**. A new Admin create/edit/renew/reserve/Trial selects exactly **one authorized Product**, not a Plan plus an independently selected Access Group. A server-side Product authorization check must combine explicit mode policy (all allowed current/future Admins or exact IDs), archived/new-selection state, Admin inbound ceiling and live validated topology. No implicit public permission merely because the legacy Access Group permission table is empty.
2. Preserve the immutable Product reference on user/paid period/pending reservation even if Owner archives Product or revokes Admin permission for **new selection**. Existing active paid users must pick up Owner's latest **valid** Product Inbound/Host selection and Host property changes; an already accepted paid pending renewal must resolve latest valid network **at activation**, without rechecking a now-revoked *new-selection* permission and without changing its paid Toman/term snapshot. Product archive must not archive its internal backing Access Group or delete still-referenced network identity; invalid network fails closed, not via fallback to all Hosts, default Product, unrestricted Node or automatic cancellation of paid service. Separate eligibility and selective access cancellation decisions need explicit future code/tests.
3. The underlying topology actually inspected provides Host→Inbound via `ProxyHost.inbound_tag` and Group→Inbound/Host plus **independent** Group→Node. Neither `ProxyHost` nor `Node` in the inspected models establishes Host→Node FK. Therefore a correct Product implementation **cannot infer Host→Node from the mere choice of Host IDs**, invent a Node relationship, copy `node_ids=[]` and claim it is safely scoped, or offer Owner a hidden independent Node selection. Reuse existing validated topology/network mapping only where it can establish the intended effective Nodes; otherwise deny unsafe access and record a deterministic error. Do not change legacy V1's historic meaning of an omitted Node scope in this audit.

# v1.1.20

- New Master installations explicitly set XRAY_LOCAL_CORE_ENABLED=false. The Panel and MySQL manage remote Nodes without starting, restarting or polling a local VPN core. Keep core configuration metadata, subscription rendering and remote Node lifecycle/provisioning. Existing deployments without this setting retain their local core; updates do not silently disconnect active Master endpoints. A deliberate combined Panel/local-core installation can set the flag true.
- Core status reports intentional local disablement. Core configuration changes and remote reconnect remain functional; the UI stops requesting disabled local logs and explains management-only mode. Disabled Master throughput is omitted from Node bandwidth data.
- Add a durable active-incident center in the shared authenticated shell, including an expanded dashboard view. Owner sees all Admins; other Admins see only themselves and descendants. Group by Admin and filter severity, username and active/resolved state with bounded pagination. Current balance, funding basis, debt percentage, configured freeze/cutoff thresholds and remaining headroom are displayed. Account ceilings, relevant quotas and near expiry also produce warnings. Inherited restrictions display a generic reason without exposing a parent's private financial data.
- Viewer receipts are independent of resolution. Seeing a warning does not remove an active problem. State changes and resolution preserve transition events; unchanged incidents refresh current values without repeated notifications. Receipts are per viewer and revision; escalation makes an older receipt obsolete.
- Separate comprehensive warning scans (default 120 seconds) from existing financial enforcement. Financial/creation/quota writers materialize known incidents in their transaction. A lightweight authenticated change stream checks the scoped event watermark every 15 seconds, revalidates authentication and releases DB connections between checks. Foreground polling every 60 seconds provides fallback; hidden tabs stop streaming/polling. The UI signals connection and stale comprehensive scan status. This is bounded notification latency after server detection, not a promise of instant delivery with a closed browser.
- Viewer polling reads indexed incident summaries, not all Users. Comprehensive policies and qualified legacy traffic warnings use bounded batches. Traffic warning reset IDs and prior event keys are fetched in batches, avoiding per-user queries. No new queue/cache service is required.
- USED_TRAFFIC dashboards show the Admin's own configured base Toman/GiB rate and explain that account duration weighting changes effective cost. Missing rates are shown as unconfigured, never as free. No prices, counters, fractional billing remainder, ledger amounts, existing factors, Access Group or network grants are rewritten.

Schema additions: admin_alert_incidents, admin_alert_receipts and admin_alert_scan_state. Replayable migration c7f3a1d9e820 follows b6e2c9f4a810. The new tables preserve active state/receipts across restarts; existing alert history is retained.

Validation covers financial transitions and exact counters, active/read/resolved separation, escalation/dedup, Owner/subtree privacy, migration replay, receipt revisions, bounded query counts, batched traffic warning dedup and management-only local/remote behavior. Public-IP discovery is stubbed in local tests to avoid external address-discovery requests; runtime behavior is unchanged.
